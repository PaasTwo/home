Admin Assistant

پایش هوشمند و خودکار پلتفرم

Admin Assistant یک عامل پس‌زمینه است که به‌صورت مداوم وضعیت Cluster را Poll می‌کند، مشکلات را شناسایی می‌کند، و با کمک هوش مصنوعی تصمیم می‌گیرد که خودش رفع کند یا به ادمین هشدار بدهد.

deployed_code_update Crash-loop Detection
memory High Resource Alert
auto_fix_high Auto Remediation
۱
Poll — جمع‌آوری وضعیت Cluster

هر ۵ دقیقه GET /api/v1/admin/cluster-status برای دریافت وضعیت node ها، pod ها، deploymentها، و رویدادها.

۲
Detect — شناسایی مشکلات

بررسی crash-loop ها، node های ناسالم، نرخ خطای بالا، و مصرف بیش از حد CPU/Memory.

۳
Analyze — تحلیل با هوش مصنوعی

ارسال IssueData به AI Provider (Ollama / Gemini / DeepSeek / OpenAI) و دریافت Analysis با Severity و Action پیشنهادی.

۴
Decide — تصمیم و اقدام

شدت low/medium: رفع خودکار از طریق Admin API. شدت high/critical: POST هشدار به Alertmanager.

۵
Report — ثبت در API Server

ثبت Issue با کامنت AI و وضعیت رفع مشکل از طریق POST /api/v1/admin/issues.

ابزار خط‌فرمان

paas2 CLI — مثل Heroku

تمام عملیات پلتفرم از ترمینال. ایجاد اپلیکیشن، استقرار، مقیاس‌دهی، مشاهده لاگ، و مدیریت متغیرهای محیطی — ایده‌آل برای CI/CD pipeline.

# احراز هویت
$ paas2 login
# مدیریت اپلیکیشن
$ paas2 apps:create my-app
$ paas2 apps:list
$ paas2 apps:info my-app
# استقرار و عملیات
$ paas2 deploy --app my-app --branch main
$ paas2 scale --app my-app --replicas 3
$ paas2 logs --app my-app --tail
# متغیرهای محیطی
$ paas2 apps:env set DATABASE_URL=postgres://...
$ paas2 apps:env list
احراز هویت دو‌Realm

Keycloak SSO با Circuit Breaker

دو Realm جداگانه برای جداسازی کامل دسترسی ادمین از کاربر. یک Circuit Breaker از تمام فراخوانی‌های Keycloak محافظت می‌کند تا خرابی IAM به سرویس‌های دیگر سرایت نکند.

manage_accounts

Admin Panel — نقش‌ها: admin
Client ID: admin-panel
person
Realm: paas2-users
User Panel + CLI — نقش‌ها: user, moderator, billing
Client ID: user-panel
electric_bolt
Circuit Breaker
پس از N خرابی متوالی، مدار باز می‌شود و جلوی Cascading Failure را می‌گیرد.

استقرار

با یک دستور، همه سرویس‌ها بالا می‌آیند

Taskfile در ریشه پروژه همه چیز را به یک سرور Remote Sync می‌کند و سرویس‌ها را به ترتیب dependency راه‌اندازی می‌کند. یا می‌توانید هر ماژول را به‌صورت جداگانه با Docker Compose اجرا کنید.

rocket_launch
استقرار کامل با Taskfile
task — Sync + Restart همه سرویس‌ها
view_in_ar
Docker Compose جداگانه
هر ماژول Compose مستقل دارد
monitoring
بررسی وضعیت
task status یا bash status.sh
# استقرار کامل با Taskfile
$ task            # sync + restart all
# یا به ترتیب با Docker Compose
$ cd database && docker compose up -d
$ cd api-server && docker compose up -d
$ cd admin-assistant && docker compose up -d
$ cd admin-panel && docker compose up -d
$ cd user-panel && docker compose up -d
# اجرای local برای توسعه
$ cd api-server && go run cmd/server/main.go
$ cd admin-panel && npm start  # :3000
$ cd user-panel && npm start   # :3001
